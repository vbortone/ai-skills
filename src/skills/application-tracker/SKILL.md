# Application Tracker

Maintain context about the user's job search across multiple tailored applications. Reads context from the working folder; surfaces it on request or when a sibling skill (typically `resume-tailor`) asks for it.

The skill is **user-agnostic**. Personal data — applications, recruiter threads, tasks, archived outcomes — lives in the user's working folder, not the skill folder. See `examples/working-folder/` for the conventions the skill expects.

## When this skill applies

Trigger when the user asks about job-search state, application history, recruiter context, or the open-task list — anything that requires reading aggregate state across multiple applications rather than tailoring a single one.

Common trigger phrases:
- *"What happened with {Company}?"* — prior-outcome lookup
- *"Did I apply to {Company} before?"* — re-application detection
- *"Any recruiters working {Company}?"* — recruiter cross-reference
- *"What's on my someday list that matches this JD?"* — task matching
- *"Summarize my pipeline / active applications."* — state aggregation
- *"Archive this application."* — write-side (P3.19; deferred)

Also acts as a callable context provider for `resume-tailor`: when a tailoring run starts, `resume-tailor`'s Step 0 can invoke application-tracker scripts to surface prior outcomes, recruiter threads, and someday matches for inclusion in `tailoring_notes.md`.

## Working-folder conventions

The skill reads context from these conventional locations in the user's working folder. Override paths via CLI flags on the individual scripts when the user organizes things differently.

| Convention | Default path | What lives there |
| --- | --- | --- |
| Active applications | `{working_folder}/Applications/<Company>_<Role>_<YYYY-MM-DD>/` | Per-application folders generated by resume-tailor. Read-only for this skill (until archive workflow lands). |
| Archived applications | `{working_folder}/Archive/Applications/<Company>_<Role>_<YYYY-MM-DD>/` | Closed-out applications. Each carries an `_outcome.md` with the result + lessons. |
| Recruiter threads | `{working_folder}/memory/people/recruiters.md` (or any single Markdown file the user designates) | Recruiter contacts with one section per active thread: name, firm, last contact, comp anchor, status. |
| Tasks | `{working_folder}/TASKS.md` | Task list with sections like `## Active`, `## Waiting On`, `## Someday`, `## Done`. The skill reads the Someday section by default. |

See `examples/working-folder/` for templates of each.

## Scripts

The skill provides three read-only context-provider scripts. Each is callable independently and emits JSON to stdout for easy consumption by the LLM or by `resume-tailor`'s tailoring workflow.

### `scripts/find_prior_applications.py`

Look up prior applications to a given company across `Applications/` and `Archive/Applications/`.

```
python find_prior_applications.py \
    --company "Acme Corp" \
    --working-folder "/path/to/working-folder" \
    [--applications-dir Applications] \
    [--archive-dir Archive/Applications]
```

Returns JSON:
```json
{
  "company": "Acme Corp",
  "matches": [
    {
      "folder": ".../Applications/AcmeCorp_DirectorEng_2026-04-15",
      "status": "active",
      "role": "DirectorEng",
      "date": "2026-04-15",
      "outcome_excerpt": null
    },
    {
      "folder": ".../Archive/Applications/AcmeCorp_HeadOfPlatform_2025-11-02",
      "status": "archived",
      "role": "HeadOfPlatform",
      "date": "2025-11-02",
      "outcome_excerpt": "Rejected after final round — feedback was framework-depth gap."
    }
  ]
}
```

Matching is case-insensitive and handles common spelling variants (whitespace, punctuation collapsed).

### `scripts/find_recruiter_threads.py`

Search the user's recruiter file for threads mentioning a company.

```
python find_recruiter_threads.py \
    --company "Acme Corp" \
    --recruiters-file "/path/to/memory/people/recruiters.md"
```

Returns JSON:
```json
{
  "company": "Acme Corp",
  "matches": [
    {
      "heading": "Kegan Smith / TalentUnify",
      "excerpt": "...Pitched Acme Corp Senior Director role 2026-05-22...",
      "line_number": 47
    }
  ]
}
```

The script returns the surrounding markdown section for each match — the LLM parses the structured fields (name, firm, last contact, comp anchor) from the excerpt at runtime.

### `scripts/find_someday_matches.py`

Scan the Someday section of `TASKS.md` for items matching keywords from a JD.

```
python find_someday_matches.py \
    --tasks-file "/path/to/TASKS.md" \
    --keywords "healthcare,clinical,HIPAA"
    [--section-heading "Someday"]
```

Returns JSON:
```json
{
  "keywords": ["healthcare", "clinical", "HIPAA"],
  "matches": [
    {
      "item": "Build a healthcare-AI artifact for portfolio",
      "matched_keywords": ["healthcare"],
      "line_number": 23
    }
  ]
}
```

## Integration with resume-tailor

When `resume-tailor` runs and `application-tracker` is loaded:

- **Step 0 (resume-tailor)** — `resume-tailor`'s Step 0 invokes the three scripts above with the JD's company + keywords. Results are appended to `tailoring_notes.md`'s "Project context" section.
- **Step 6 (resume-tailor)** — `resume-tailor` quotes the prior-outcome excerpts (if any) verbatim in `tailoring_notes.md`'s "Prior outcomes" section.

`application-tracker` does not modify `resume-tailor`'s output paths or DOCX rendering — it's strictly a context provider.

## Out of scope (for now)

- **Archive workflow** (P3.19 in the resume-tailor improvement plan) — moving an active application to `Archive/Applications/`, stubbing `_outcome.md`, updating recruiter/task state. Deferred; the skill is read-only for the MVP.
- **Recruiter thread parsing** — the skill returns matched markdown sections; it does not enforce a structured schema for recruiter entries. The LLM extracts structured fields per recruiter at runtime.
