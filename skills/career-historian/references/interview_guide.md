# Interview Guide

How to run the looped interview. The mechanics matter as much as the questions: a good interviewer gets stories and numbers; a bad one gets a tired user and a list of nouns.

## Loop etiquette

- **One question per turn.** The user answers conversationally; you capture, then ask the next single question. If you catch yourself writing a numbered list of questions, stop and pick the best one.
- **Acknowledge before probing.** A one-clause reflection ("a payments migration under a hard deadline — got it") tells the user they were heard and gives them a hook to correct you cheaply.
- **Re-prompt the loop explicitly.** Every loop iteration ends with an invitation that names the exit: *"Another project, or move on to skills?"* The user should never wonder how to leave the loop.
- **Stop on the first stop signal.** "Stop", "done", "that's it", "move on", "enough", "let's pick this up later" — all of them end the loop immediately. Save, then either move to the next track or wrap up, whichever they signaled.
- **2–4 probes per item on the first pass.** The gap-analysis pass exists precisely so you don't have to wring every item dry in real time. Get the skeleton (what, role, when, outcome), flag the rest as open questions.
- **Match the user's energy.** Short answers late in a session mean wind down — offer to wrap rather than open a new track.

## Probing techniques

- **Quantify**: "Roughly how many users / requests / dollars / people?" Accept estimates and record them as estimates: `~40% (user's recollection)`.
- **Scope and scale**: team size, budget, duration, traffic, number of stakeholders. Scale is what separates two identical-sounding bullets on a resume.
- **Before/after**: "What was true before you did this that wasn't true after?" — the cleanest path to an outcome statement.
- **STAR completion**: if a story has Situation and Task but no Action or Result, ask for the missing half. Behavioral interviews will.
- **Role isolation**: "What part was specifically yours?" Teams ship projects; resumes need the user's verbs.
- **Failure and friction**: one well-told obstacle ("the vendor API fell over two weeks before launch") is worth three smooth bullets in an interview setting. Ask once per project, don't push.

## Question banks

Use these as starting points, not scripts. Adapt to what's already in the dossier — never ask what a mined document already answered.

### Projects track

Openers:
- "What's the first project from your time at {Company} that comes to mind?"
- "What were you hired to do there — and what did you actually end up doing?"
- "What project from that era still comes up in interviews or conversations?"

Per-project probes (pick 2–4):
- "What problem did it solve, in one sentence?"
- "What was your specific role versus the team's?"
- "What was the tech stack / method / toolchain?"
- "How big — team, users, budget, timeline?"
- "What's the result you'd put a number on?"
- "Anything go sideways that you fixed?"

Loop re-prompt: *"Another project from {Company}, or move on?"*

### Skills track

Openers:
- "What skills did you pick up at {Company} that you didn't have walking in?"
- "What were you the go-to person for?"
- "Anything you exhibited there that you'd already mastered elsewhere — leadership, architecture, vendor wrangling?"

Per-skill probes (pick 1–3):
- "Where specifically did you use it?" — cross-link to a captured project when possible instead of asking for new detail.
- "How deep — daily driver, working knowledge, or supervised others using it?"
- "When did you last use it?" (recency matters to resume-tailor's skills ordering)

Loop re-prompt: *"Any other skills from that period — technical or otherwise?"*

### Contacts track

Openers:
- "Who from {Company} would you want as a reference?"
- "Who did you work with most closely day-to-day?"
- "Any manager, skip-level, or stakeholder who saw your best work?"

Per-contact probes (pick 2–4):
- "What was their title then — and where are they now, if you know?"
- "What did you work on together?"
- "Would you actually ask them to be a reference — yes, maybe, or just a good name to drop in conversation?"
- "Do you have current contact info, or are they a LinkedIn-lookup-later?"

Loop re-prompt: *"Anyone else worth recording — even a 'maybe'?"*

## Capturing answers

Write into the dossier sections as the loop runs (or buffer and flush at each loop boundary). Every captured item gets:

- The user's facts in their vocabulary — don't translate "we un-hosed the deploy pipeline" into corporate-speak; resume-tailor handles register at tailoring time, and the original phrasing carries information.
- A `Source:` line — `interview YYYY-MM-DD`.
- Estimate markers where the user guessed.

When an answer spans tracks (a project answer that names a contact), capture both sides immediately rather than re-asking later.
